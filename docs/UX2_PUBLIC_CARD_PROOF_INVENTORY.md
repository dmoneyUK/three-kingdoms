## Projection and privacy boundary

- Producers use exact server card objects captured from their authoritative Hand, Equipment, or deck/Judgement transition. The `@card`/`@cards` event ID is copied into each typed proof; repeated event/effect IDs, mismatched card IDs, unsupported effect/class pairs, malformed zones, hidden/private events, and invalid root links fail closed in `game/presentation-v2.ts` and `game/presentation-snapshot.ts`.
- Snapshot projection copies only the allowlisted proof fields and public physical-card identities. Private Draw events remain excluded; Equilibrium replacement Draw IDs are absent from other viewers' proof snapshots. No hidden Hand index, local selection, or client-derived legality is used as proof.
- Standalone skill costs and conversions are self-rooted in their genuine public physical-card event. Where a separate causal card exists, proof names its exact event/resolution: Necromancy → revealed Judgement; Stauchness, Rock Cleaving Axe, Frost Sword, Kirin Bow, Green Dragon Blade, and Eight Trigrams → their actual Attack/Judgement root.
- Yin-Yang Swords' selected Hand identity stays absent from every public view while the private choice is open. After the server accepts the selection, the same exact card is moved to the public discard and its identity is emitted with the root Attack proof. A missing root link suppresses the effect proof; it never derives a card identity from the text log, timeline order, Hand count, or discard array.
- Focused Worker/D1 suites exercised by W1 are listed in the HANDOVER after validation. This file records proof state only; §10.9 renderer, layout, and visual acceptance remain separate tasks.
