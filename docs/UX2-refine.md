## R. Reusable UX2 contracts — canonical patterns for future features

These patterns are **CURRENT product design**, not old implementation steps and not an automatically executable task list. Specific approved card/skill exceptions in original sections override a generic example; server rules always remain authoritative. New UX work should **reuse these shared contracts and name only the necessary variant**, rather than copy whole renderer, picker and phone matrices.

### R1. Server authority and truthful public proof
**`CurrentAction` alone grants the viewer legal Play/Respond/Pass/Select/Skip**; client visuals cannot reconstruct target legality. **`PresentationSnapshot` / `PresentationClientView` supply proven PUBLIC event facts**, including actual actor/target/root/interaction/checkpoint/event IDs, sequence, true physical IDs and outcome. Anonymous/private Hand identities, hidden roles, uncommitted Negation intents, private choice/card acquisition stay viewer-scoped and never leak via H4/PAC/Inspector or TEST SWITCH. Missing/mismatched proof **fails closed**; no guessed animation, card, actor, damage or resolution. Preserve exact server card conservation and stale/replay checks.

### R2. Three distinct information surfaces (H4 / PAC / Local Console)
| Surface | What it says | Examples and hard constraints |
| --- | --- | --- |
| **H4 — centred public historical fact** | What the server confirms **HAS happened**, and only that | `King played Duel on Test Player 4.`; `Test Player 3's Negation cancels King's Duel effect on Test Player 4.`; `Test Player 2 counters Test Player 3's Negation. The Duel effect on Test Player 4 is restored.`. NEVER add possible next actions, phase guidance, private locks or a duplicate EFFECT TRIGGERED box. |
| **PAC — compact PUBLIC next-step/activity** | Proven current public turn/next actor or shared response phase | `Waiting for counter responses`, `Negation can restore the Duel effect on Test Player 4.`, `Waiting for Test Player 3 · Duel`; during secret shared Negation use generic `Waiting for Negation responses`. No named hidden responders, guessed private options or submitted counts. |
| **Local Dock Console — owner-private decision** | Only actions/options the authenticated viewer can currently take | `Select 1 card and 2 Duel participants`, `You passed. Waiting for the other players.` if own lock is server confirmed; legal buttons and selection stay here. Not a source for PUBLIC PAC/H4. |

Use **player names from proven player IDs** in public narration, not Hero names unless the statement explicitly names a Hero/skill. Keep concise exact English copy and chronological correctness. H4 is a **single stage-fixed horizontal anchor**, not attached to CardFace motion; may wrap naturally beyond two lines, never clip meaningful names. PAC stays centred low, separated from Local Dock, **timer yields to PAC** (440px safe four-player PAC target ~340 CSS px, only 320–340px if genuinely constrained). No new duplicate toast or old relation graph. See §10.25.1–.2 and accepted H3/H4.

### R3. Single true physical CardFace journey and viewer-relative history
For every PUBLIC genuinely committed CardFace: **one central genuine CardFace up to ~4s**, interruptible by a newer committed event; then physical movement around **380ms**, then PARK **one same physical card** at its proven actor/material owner's genuine Seat/Dock/zone per event semantics. Attack/Dodge, Negation chain, Hero COST/Equipment EFFECT, Duel and grouped effects keep exact event identity and actual source/target attribution. **Duel and proven Attack exchanges retain chronological per-Seat history** (TOP stacks vertically; SIDE fans inward; Local above Dock), with readable chain-global ordinals for genuine committed responses; never number Pass/private intent. On viewer-switch/resize **reproject parked coordinates without animating from the old viewer's seat**. The public physical renderer, status text and private decision have distinct clocks: a visual tail cannot block legal CurrentAction or resurrect a static duplicate after PARKED. Never rebuild green/red graph arrows or permanent deck/discard piles.

### R4. Reusable real-card-backed Hero/Equipment COST, CONVERSION and EFFECT frame
Use **one compact neutral/antique-gold frame** with actual printed Hero/skill/Equipment label **ABOVE genuine public physical CardFace(s)**, one factual H4 explanation and no second same-event notice. For one paid card show one genuine image; two side by side; three or more in a contained inspectable strip/grid without hiding a paid card. Server-proven `activationOwnerId`, `materialOwnerId`, true `physicalCardId`, source/recipient/root/proven outcome and public disclosure must agree. A paid target-owned card parks with the **target/material owner**, not necessarily the activator. AS ATTACK / AS DODGE / AS PEACH / AS OVERINDULGENCE conversions keep **original card art and suit/rank** plus proven `AS` semantics, never a counterfeit converted face or invented play. On no safely public physical card, use a **text-only** proven outcome; private draw/replacement remains concealed. No generic Deflection redirect assumption for unrelated skills. Covers 30 Standard Heroes/46 skills, 9 Weapons, 2 Armors, 2 Mounts; official game semantics are sourced from repository rules. See §10.9.

Spectators can SWITCH/Inspect but never choose or see private candidates. Safe interactive controls, transparent pass-through outside the frame; avoid full-window input shields, H4/Hand/timer/Seat overlaps, forced page scrolling. **Retaliation and other special pickers use same shell vocabulary, not automatic copy of different action semantics.** See §§10.17, 10.22.

## 3. The one public-card presentation lifecycle

For each newly **server-confirmed, visible public played-card event**:

1. **REVEAL — user-approved policy B, 2026-10-14:** A server-committed real CardFace is shown at readable Hand size in the centre for **4,000ms from its first visible large painted frame by default**. **Exception: a NEW authoritative, committed public response/counter card belonging to the active interaction may interrupt this display early**, taking centre focus immediately. It then receives its own default 4s clock, which may likewise be interrupted by an even newer committed response. Polling, phase/CurrentAction changes, speculative/failed/private choices, timeout/Pass and a mere settlement message cannot interrupt. Supersedes the older ~500–800ms timing. See §8.7.
2. **MOVE:** On normal 4s expiry, move/shrink that same CardFace over **380ms** to its true author's Seat/Dock. **On valid committed-response interruption**, start parking the older card immediately (380ms motion when practical, without delaying the NEW large card), while the newly accepted card takes centre focus right away. Avoid two simultaneous full-size centred cards, ghost duplicates and incorrect card ownership. Use no connecting stroke.
3. **PARK/WAIT:** For ordinary public reactions, keep the public thumbnail at the genuine author's Seat/Dock while waiting. **Duel exception:** preserve the full committed-card history *split by the actual author*, stacked vertically below top Seats, extended inward horizontally at left/right Seats, and horizontally above the local player's Dock (§8.1). Every card carries its real cross-player order index. Never show an uncommitted response. The Local Dock alone presents `CurrentAction`.
4. **RESPONSE:** A later genuinely committed public response gets its **own** centre reveal and then parks before **its own author**, independent of who is currently the viewer.
5. **SETTLEMENT:** Show a **server-proven** blocked/damage/negated/otherwise resolved result close to the affected real Seat/Dock. Initial result readability target **~2 seconds**; next independent proven action supersedes old display promptly. Keep the author cards long enough to understand the result; no animation can hold up gameplay.
6. **RETIRE:** Remove expired public cards, overlays and labels without a ghost copy or sudden reappearance. **An actual confirmed new response may supersede the current centre card under policy B;** merely receiving a room update or newly pending response must NOT. Maintain real history and server gameplay deadlines independently.

**Identity/dedupe requirements:** Use authoritative event/root/interaction/actor/card identities. Polling and harmless rerenders never restart OR prematurely finish a reveal. A newly observed genuine event may reveal once; historic events on reload/view-switch reconstruct parked truth. **Policy B: never queue a newly committed response behind an earlier card's remaining four seconds.** The new verified response takes centre priority, and earlier cards park at their real owners. If a poll contains multiple committed events, respect verified causal order, keep all physical identities, and let the latest eligible response take centre; never create fake cards or block game decisions.

**Reduced motion:** Do not translate/scale animate. Show a readable, full-size static centre card for **up to four seconds**, shortened only by a subsequent genuine committed response under Policy B, then switch to the true Seat/Dock without travel. Preserve accessible announcements without duplicates.

**Zero graph elements:** The new public card presenter must never render SVG relationship connectors, coloured authored/effect strokes, arrows, line branches or graph-only card nodes. Implement geometry for *positioning moving card sprites*, not for representing relationships.

### 9.1 Deterministic window protocol

1. **Open:** When an effect may be Negated, create one server-authoritative confidential window for **ALL living seats**, irrespective of private cards/skill providers. Persist opaque windowId, canonical seat-priority start, ordered snapshot of the living seats, effect/root causal identity, openedAt, **immutable maximum deadline = openedAt + 8,000ms** and private submissions. Keep existing source/target starting anchors for ordinary Stratagem, Judgement, Group/AOE and Harvest. Everyone sees the same remaining clock until settlement; nobody sees others' cards, intent type, submitted seats or completion count.
2. **Offer in parallel to everyone:** All living players receive their own private CurrentAction. If the server finds any genuinely legal Negation card or Hero-skill/conversion provider, offer those legitimate options PLUS Pass; otherwise offer **Pass ONLY**. **Never automatically submit Pass just because the player lacks a provider.** The no-card player must explicitly tap Pass for the window to close early; doing nothing is allowed and becomes implicit Pass only at 8s timeout. Confirm stores a secret intent, not a public played card; unrelated actions remain disabled.
3. **Individual lock and early-finish eligibility:** A server-accepted Negation intent **or explicit Pass** is persisted and locked for that player's window; show only to them “Response submitted — waiting”. Duplicate identical submission stays idempotent, conflict rejects. **After each successfully persisted submission**, the server may check whether **every ID in the original living-seat snapshot** has a valid persisted response. If yes, claim/settle this window immediately without waiting for T0+8s. If any seat is missing, keep the original deadline; neither polling nor a client's guess may close it. **Never auto-submit Pass or remove no-card players from this check.** Do not publish completion counts, submitted IDs or individual choices.
4. **Close at the earlier of two authoritative conditions:** **(A)** every living seat in the window snapshot has **explicitly persisted Negation intent OR Pass**, or **(B)** the immutable T0+8s deadline is reached. The server, not React/polling, atomically claims settlement once and validates all accepted submissions; if condition A was reached at time T, do not accept late duplicate/conflicting writes after the claim. The actual winner is the first valid Negation by canonical seat order, **NEVER the fastest submitter**. Losing intents do not cost cards. If no valid winner, settle the underlying effect. Concurrent final submits, timer expiry and retries must not double-close, consume twice or skip a legitimate responder.
5. **Commit one physical card:** For the winning intent only, perform the usual authoritative card consumption (exactly once), Negation effect toggle, log/public card event, real actor identity and causal history. All losing intents are voided with **zero cards consumed**, even if they submitted earlier/later, and no fake card is revealed. Each player's own private final status can reflect whether their intent was used; other players see only the accepted public card. Ensure card conservation and existing hero provider legality.
6. **Counter window:** If a Negation wins, open a NEW shared 8-second window against that actual Negation. Seat-order priority starts with the **next living seat after the actual committed Negation's actor**, wrapping around; include every living seat (including the last actor upon wrap-around, if a legal provider still exists). All previous losing intents are discarded, **never automatically carried over** as counter-Negations, because the tactical decision/target is different. Repeat for counter-counter-Negation without arbitrary chain-depth cutoff; preserve genuine legal game termination and event proof.
7. **Final settlement:** When a window closes with no accepted Negation, settle the current negated/restored effect exactly once. A Duel must NEVER begin its Attack exchange until the root shared window **and every genuine counter window** complete. Preserve per-target cancellation semantics for multi-target effects.

### 9.2 Concrete seat example and priority

- Shared window #1: all five living seats privately receive Negation/Pass; seats 2 and 4 submit actual Negation intents, seats 1, 3 and 5 **explicitly Pass**. When the **last** of these five submissions is persisted (possibly before 8s), the server settles early: **seat 2 wins** by seat priority, only seat 2's Negation becomes public, seat 4 retains their card. If seat 5 stays silent, the window instead remains open until 8s; the winner is still seat 2.
- Shared window #2: a fresh **up-to-8s** confidential counter window goes to ALL living seats, priority **3→4→5→1→2**. Seat 4 may independently submit a counter intent; it becomes a real public card **only when all five explicitly respond or the new 8s timer expires**, if chosen by priority. If seat 4 wins, Duel is restored and a separate window #3 starts at seat 5.
- After the first or any subsequent shared window that closes with no successful new Negation, resolve the current root effect state. Seat 3 starts the Duel Attack exchange **only if Duel ultimately remains active**.
- If only seat 4 submits Negation and all other seats **explicitly Pass**, seat 4 wins **immediately after the last response**. If others are silent, the server waits until 8s even if they lack Negation cards. If everyone Passes explicitly, settle early with no winner; if nobody responds, settle at 8s. No seat-by-seat 8s turns.
