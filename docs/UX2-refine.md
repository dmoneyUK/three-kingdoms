## R. Reusable UX2 contracts — canonical patterns for future features

These patterns are **CURRENT product design**, not old implementation steps and not an automatically executable task list. New UX work should **reuse these shared contracts and name only the necessary variant**, rather than copy whole renderer, picker and phone matrices.

### R0. Design reuse and precedence — one source per concern

**Choose the shared solution first:** `CurrentAction` = private legal decisions (R1); public proof = true events (R1); **H4** = committed past, **PAC** = proven next step, **Local Console** = my action (R2); **one physical-card Journey** (R3); **one card-backed skill/equipment Frame** (R4); **one nonmodal choice shell** (R5); **one current Seat/Inspector/equipment grammar** (R6); **one recipient-private new-card arrival** (R7). Reuse a single implementation/presentation owner; no second banner, overlay, result-card renderer or duplicated picker for a new card type.

**Only specify a variant where the game is different:** whether a Negation blocks Steal's **gain**, Dismantle's **discard**, Borrowed Sword's **forced Attack/Weapon consequence**, Harvest's **current recipient's pick**, or a delayed Judgement. Keep original actor/target/physical identity and actual server-owned outcome. **The owner has now also explicitly accepted the shared Negation and Dismantle full flow.** Individual different card mechanics still require correct source-defined behavior; do not invent separate phone-test evidence for them. An accepted component is reusable by default; add a new task only for a measured deviation and explicitly approved fix.

**Source and status precedence:** server/game law > latest explicit owner design decision > reusable common contract > card-specific addition; **specific exceptions do not rewrite the generic shared component without approval**. Accepted = owner phone PASS in an actual named scope; age-archived = retired technical backlog with no invented PASS; pending = a real remaining phone review. Preserve best-known original section anchors only for references, and find older suffixes in Git.

### R1. Server authority and truthful public proof
**`CurrentAction` alone grants the viewer legal Play/Respond/Pass/Select/Skip**; client visuals cannot reconstruct target legality. **`PresentationSnapshot` / `PresentationClientView` supply proven PUBLIC event facts**, including actual actor/target/root/interaction/checkpoint/event IDs, sequence, true physical IDs and outcome. Anonymous/private Hand identities, hidden roles, uncommitted Negation intents, private choice/card acquisition stay viewer-scoped and never leak via H4/PAC/Inspector or TEST SWITCH. Missing/mismatched proof **fails closed**; no guessed animation, card, actor, damage or resolution. Preserve exact server card conservation and stale/replay checks.

### R2. Three information surfaces — one shared H4/PAC/Console design and approved copy

**One owner for each concern.** H4 is a **server-confirmed PUBLIC past fact**; PAC is the **proven PUBLIC current or possible next step**; the Local Dock Console gives only the authenticated viewer's **private authorized action**. None may obtain its authority from another surface's text or a guessed timer/DOM state. Public copy uses real **PLAYER names** resolved from proven IDs (Hero/skill titles are different), actual actor/target/effect and true event order.
