## 0. Product mission and current verdict

**This is a new architectural execution board, NOT UX2 visual redesign.** The game already has accepted canonical gameplay, genuine CardFace, H4/PAC/Console, choice semantics and mobile UI. They are durable constraints. UX3's purpose is to improve **one owner per concern** (authenticated RoomSession, command/submission, coherent snapshots, public event playback, viewport measurement, modular rendering) with measured client performance and predictable reconnect/multiroom behavior; retain every accepted UX2 look, touch, card history, animation duration, privacy and canonical rule.

**Why now — independently inspected source at the fork:** UX2 `app/page.tsx` is ~14,130 lines with overlapping Home polling/room mutations, presentation effects, timers and refs; `app/public-card-display.tsx` ~7,616 lines with many DOM measurement/animation lifecycles; shared `PublicStageLayoutProvider` and server `PresentationSnapshot` already exist. Source size is coupling evidence, **not** measured CPU or mobile jank proof. No replacement engine, framework, WebSocket, Durable Object or wholesale CSS rewrite is approved.

**Two outcome tracks + one gate:**
- **G — GAME-COMPLETE:** actual independent human and 1-human+3-Bot full Standard match, true winner, real device and refresh/rejoin. UX3 must not compromise these.
- **M — MULTI-ROOM:** multiple simultaneous rooms with viewer-safe consistent state, bounded requests/re-render/geometry and no cross-room privacy leak; target 1/4/8 active-room synthetic measurements, **not** an approved live-capacity claim.
- **S — SAFETY:** viewer/room secrecy, one canonical server, unchanged legal action semantics, exact public proofs, protected staging/prod and reproducible CI. S blocks release, not an excuse for indefinite standalone investigations.

## 3. UX3 architecture — one owner per meaning, no gameplay redesign

### UX3-ADR-001 — one typed authenticated RoomSession and CommandGateway

Current `app/page.tsx` Home mixes room/token, GET polling, POST mutation, heartbeat, retry, presence, timer-advance and room-switch. Extract **one** room/viewer-scoped transport session with identity `roomId + authenticated viewerId + session epoch` (private token retained only in memory/session-owned transport, never logged/cache). Server remains authority for `CurrentAction`, `actionRevision`, pending and deadlines. Reuse `game/room-poll-recovery.ts`, `game/room-safety.js`, `game/protocol.js`, `app/page.tsx` behaviors; do not introduce parallel Fetch controllers or a new state framework.

Commands carry exact actor/expected revision/submission ID; deduplicate the *same submission* but allow genuinely independent shared-window responders. An earlier GET/POST response must never overwrite a newer accepted viewer snapshot or reopen an old private viewer; `409` performs safe resync. Do not compare actionRevision alone as an all-fields view version. Timer expiry and `advance_timers` server actions remain unchanged until separately proved server recovery replaces them.

### UX3-ADR-002 — immutable viewer-safe RoomSessionStore, not a second game state

One subscribed latest accepted room snapshot + error/offline/retry state. Pure selectors for Dock, Hand, seats, current action and public presentation; React `useSyncExternalStore` where helpful, without adding a state library by reflex. Immutable room/viewer/epoch ownership and monotonically accepted proof/order; per-viewer privacy clear on leave, TEST SWITCH, role/seat change and bad token. No shared viewer-private CDN cache or stale hand on phone refresh.

### UX3-ADR-003 — one public PresentationCoordinator and event cursor

Retain **server** `PresentationSnapshot`, `PresentationV2`, ordered public event identity, physical card provenance, existing `game/presentation-client.ts`, `game/public-presentation-turn.ts`, `app/public-presentation-routing.ts` and accepted public appearance. Introduce pure reducer/statechart `HYDRATE → REST/CHOICE → PRESENTING → SETTLEMENT/HOLD → RECONCILE → FINISHED` indexed by `room + viewer + interactionId + root/frame/ordinal + eventId` as appropriate. No replay on refresh/history truncation or lost event; cosmetics must never block legal human response. Migrate **one real event family at a time**, use identical H4/PAC/Console, read hold, Duel seat-ordered Attack history and accepted retirement rules; retain not-yet-migrated distinct event families only; within each authorized slice retire superseded owners/fallbacks before technical completion per §6C. No silent fallback to replaced path.
