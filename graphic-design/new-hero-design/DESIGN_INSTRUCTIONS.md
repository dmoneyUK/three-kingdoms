# WTK New Hero Graphic Design + GitHub Upload Workflow

## Goal

Create a complete WTK hero collection that feels like one game world while making every hero visually distinctive.

The collection should have consistent quality and art direction, but must **not** look like the same character composition repeated with different costumes.

## 1. Core art direction

Use a bright, cinematic ancient-Chinese / Three Kingdoms fantasy style.

General qualities:
- bright and readable lighting
- rich ancient-Chinese clothing, armour, silk, lacquer, jade and gold details
- strong faction colour identity
- cinematic atmosphere
- highly recognizable hero silhouettes
- hero remains the main visual focus
- no game UI, card frame, hero name, health, skill panel or gameplay text baked into standalone hero artwork

Faction identity should be recognizable without forcing every member of the same faction to use identical compositions.

Examples:
- Wei: blue, black, steel, gold
- Shu: jade green, ivory, warm gold
- Wu: red, crimson, turquoise, river/warship influences
- Qun / others: hero-specific palettes

## 2. Character diversity — very important

Every newly designed hero should deliberately differ from previously approved heroes.

Before generating a new hero, review the existing redesigned collection and vary several of the following:

### Character appearance

Use diversity in:
- age
- build
- height impression
- hairstyle
- facial hair
- mask style
- helmet/headpiece
- armour versus robes
- heavy versus light clothing
- noble, scholarly, warrior, assassin, commander or strategist presentation

Do not make every male hero:
- young
- muscular
- long-haired
- masked in the same style
- wearing the same armour proportions

Masks can be a recurring WTK motif, but every mask should have a different:
- shape
- material
- coverage
- decoration
- faction influence

## 3. Action / pose diversity

Do **not** default every hero to:
- standing front-facing
- holding a sword
- one hand extended
- waist-up portrait

Use different actions depending on the hero.

Possible actions include:
- commanding troops
- charging
- turning toward an enemy
- drawing a weapon
- blocking
- attacking
- preparing a strike
- raising a spear
- holding a bow at full draw
- signalling cavalry
- reading or manipulating a strategy map
- casting / supernatural skill activation
- seated command pose
- walking through a battlefield
- looking over the shoulder
- dismounting
- mounted cavalry charge
- standing beside a horse
- overlooking troops from a wall or hill
- quiet strategist pose
- defensive stance
- wounded but defiant stance
- victory pose
- duel-ready pose

The pose should communicate the hero's personality and gameplay identity.

## 4. Position / composition diversity

Vary where the hero appears in the frame.

Possible compositions:
- left third
- centre
- right third
- low-angle centre
- high-angle view
- close portrait
- three-quarter body
- full body
- very wide environmental composition
- foreground hero with distant army
- hero entering frame from one side
- hero viewed partly from behind
- mounted hero occupying diagonal composition

Avoid repeatedly centering every hero in exactly the same way.

## 5. Facing-direction diversity

Actively vary facing directions across the hero collection.

Use combinations such as:
- facing viewer-left
- facing viewer-right
- almost frontal
- three-quarter left
- three-quarter right
- profile left
- profile right
- back-three-quarter looking toward camera
- looking upward/downward
- looking toward an off-screen opponent

Adjacent heroes in the redesign sequence should preferably not use the same facing direction and pose.

Example:
- Cao Cao: strong low-angle commanding composition
- Liu Bei: opposite-facing profile / three-quarter composition

Continue this principle for future heroes.

## 6. Weapon diversity

Do not give every hero a generic sword.

Use weapons appropriate to the hero's identity and historical/game inspiration.

Possible weapon families:
- jian sword
- dao / sabre
- podao
- spear
- serpent spear
- halberd / ji
- bow
- dual weapons
- fan
- staff
- axe
- polearm
- ceremonial weapon
- strategist objects such as fan, scroll, seal or command tablet

Weapons should affect the pose and silhouette.

Research the hero's established Three Kingdoms identity and Dynasty Warriors / 真·三国无双 weapon and moveset language for inspiration when useful.

Do **not** directly copy copyrighted Dynasty Warriors character designs.

Create an original WTK interpretation.

## 7. Mounts / mounted hero diversity

Some heroes should use horses or other appropriate battlefield mounts when this improves the character identity.

Possible treatments:
- hero mounted and charging
- hero calmly commanding from horseback
- horse rearing
- horse shown side-on
- rider viewed from low angle
- hero dismounting
- hero standing next to the mount
- mount partially visible in foreground
- cavalry formation behind hero

Do **not** put every hero on horseback.

Mounted compositions should be reserved for characters where cavalry or battlefield command makes visual sense.

The horse/mount should have its own:
- armour
- tack
- faction decoration
- silhouette
- pose

Avoid reusing exactly the same horse design.

## 8. Background diversity

Hero artwork may use detailed cinematic backgrounds.

Vary backgrounds according to the hero.

Possible environments:
- fortress courtyard
- city wall
- battlefield
- cavalry field
- riverbank
- naval fleet
- warship deck
- mountain pass
- bamboo forest
- palace
- command tent
- burning battlefield
- snow
- rain
- mist
- sunrise
- sunset
- clear blue daylight
- moonlit scene
- storm
- autumn battlefield
- river crossing
- siege
- army camp

Backgrounds should support the hero's story rather than simply decorate the image.

Avoid giving every hero:
- the same castle
- the same blue sky
- the same army formation
- the same banners
- the same mountain background

**Important:** this background-diversity rule applies to hero art.

The game board itself should remain much calmer:
- ivory
- rice paper
- silk
- subtle ink
- cloud/water motifs

Do not turn the gameplay board into a busy hero-style battlefield scene.

## 9. Camera / lighting diversity

Vary cinematography.

Camera examples:
- low angle
- eye level
- slightly elevated
- close-up
- medium shot
- full-body
- wide cinematic shot
- dynamic diagonal framing

Lighting examples:
- bright daylight
- warm sunset
- cool dawn
- firelight
- misty daylight
- storm light
- strong rim light
- reflected river light
- palace lantern light

Maintain overall readability.

Do not return to the old extremely dark style where characters become difficult to recognize.

## 10. Hero uniqueness check before generation

Before creating each new hero, compare it with already approved heroes.

Check:
- Is the pose different?
- Is the facing direction different?
- Is the character position different?
- Is the camera angle different?
- Is the weapon silhouette different?
- Is the background different?
- Is the lighting different?
- Is the clothing/armour silhouette different?
- Is the mask/headpiece different?
- Would a mount improve this hero?
- Does the image express this particular hero's personality or skill?

If the new concept looks too similar to an existing hero, change the composition **before** generating it.

Aim to change at least 4–5 major visual elements compared with the most similar existing hero.

## 11. Keep a design record

For every approved redesign, record its major visual characteristics in:

```text
graphic-design/new-hero-design/README.md
```

Example:

### Cao Cao
- faction: Wei
- palette: blue / black / gold
- orientation: commanding three-quarter / low angle
- face: black-and-gold ornamental mask
- weapon: sword
- secondary prop: ceremonial ritual cup
- action: commanding / ruler pose
- background: Wei fortress and soldiers
- lighting: bright daylight / warm sunlight
- mount: none

### Liu Bei
- faction: Shu
- palette: jade / ivory / gold
- orientation: profile / three-quarter facing opposite Cao Cao
- face: ivory-and-gold mask
- weapon: sword
- action: open-hand leadership gesture
- background: bright Shu battlefield / banners
- lighting: clear daylight
- mount: none

Use this information when designing the next hero to avoid repetition.

## 12. Approval and staging rule

When the user clearly approves a final hero design, such as:
- "I like this one"
- "use this design"
- "save this hero"
- "put this in the project"
- "upload this hero"
- "this one is final"

Treat it as an approved **design candidate**.

Do **not** replace the production hero immediately.

Store it under:

```text
graphic-design/new-hero-design/<hero-slug>/<hero-slug>-new-design.avif
```

Examples:

```text
graphic-design/new-hero-design/cao-cao/cao-cao-new-design.avif
graphic-design/new-hero-design/liu-bei/liu-bei-new-design.avif
graphic-design/new-hero-design/sun-quan/sun-quan-new-design.avif
```

## 13. Production asset safety

Do **not** change:

```text
public/hero-*
```

Do **not** change live `HERO_ART_BY_ID` mappings or equivalent production mappings.

Do not mix the old hero collection with the new redesign collection.

The final production replacement happens together after the user approves the complete hero/card redesign set.

## 14. Image preparation

When the approved image exists in the ChatGPT conversation:
- locate the actual generated/uploaded image
- use the original image bytes rather than a screenshot
- preserve good portrait/card quality
- preserve the intended aspect ratio
- convert to AVIF when practical
- compress reasonably without visibly degrading the artwork
- do not regenerate the artwork merely to upload it

## 15. GitHub upload workflow

Preferred process:

1. Read current GitHub `main` HEAD.
2. Prepare the approved image.
3. Create/upload the binary Git blob.
4. Add it to:
   ```text
   graphic-design/new-hero-design/<hero-slug>/
   ```
5. Update:
   ```text
   graphic-design/new-hero-design/README.md
   ```
6. Create the Git tree.
7. Create the commit.
8. Fast-forward `main`.
9. Never force-push.

## 16. Binary-upload fallback

If direct binary GitHub upload is unavailable:
- materialize the conversation image
- convert it to a reasonably sized AVIF
- use a temporary branch/upload mechanism if required
- reconstruct the binary on GitHub
- validate the resulting image
- remove all temporary chunks/scripts/workflows
- then update main

Temporary uploading infrastructure must **not** remain in `main`.

## 17. Verify after every upload

After pushing an approved hero, verify:
- image exists on remote main
- correct repository path
- valid image/blob
- README lists the hero
- README describes the visual design
- no temporary upload files remain
- no temporary workflow remains
- production `public/hero-*` asset remains unchanged
- no live hero mapping has changed

Only tell the user the upload succeeded **after verification**.

Report:
- hero name
- repository path
- final file format
- commit SHA

## 18. Collection-level diversity target

Across the full hero collection, deliberately maintain variety.

Do not allow the collection to become:

> 10 heroes → all standing → all waist-up → all looking left → all holding swords → all in front of castles → all wearing similar masks

Instead aim for a collection such as:
- commander standing at fortress
- mounted cavalry general charging
- strategist seated with fan/map
- spear warrior attacking
- archer drawing bow
- naval commander on warship
- duelist in defensive stance
- ruler overlooking army
- warrior walking through rain
- general in snow/mountain pass
- hero beside horse
- supernatural/skill-activation composition

Consistency should come from:
- rendering quality
- ancient-Chinese design language
- faction identity
- WTK visual motifs

Diversity should come from:
- character
- pose
- action
- position
- facing direction
- weapon
- camera
- environment
- lighting
- mount
- props
- silhouette

Both **consistency and diversity** are required.
